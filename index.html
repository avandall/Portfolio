PROJECT 01 • REAL-TIME AI VOICE ENGINE Interactive Language Learning

Multi-Model Architecture & Low-Latency Voice Pipeline

A real-time conversational speaking platform for interactive English learning that solves the critical 3–5 second audio turnaround bottleneck through parallel dual-model dispatching and WebSocket chunk streaming.

PYTHON FASTAPI WEBSOCKET ELEVENLABS ASYNCIO

🎯 Key Production Bottlenecks

  • ⚠️ High Turnaround Latency: 3–5s wait between user speech and audio response ruined conversational flow.
  • 🎙️ Monotone Prosody: Standard TTS voices lacked emotional dynamic nuance and distinct character personas.
  • 🔄 Repetitive Dialogue: Unconstrained LLM generation defaulted to generic filler conversations disconnected from curriculum goals.

⚙️ Technical Decisions ("Under the Hood")

  • ⚡ Parallel Dual-Model Architecture: Decoupled interaction into Model 1 (User streaming reply) and Model 2 (Async background grammar/CEFR evaluation worker with 0ms UI delay).
  • ⏱️ Sub-200ms Latency Masking: Pre-buffered instant filler clips ("Hmm...", "Well...", "Let me see...") play within 150ms while LLM chunks generate.
  • 🎭 ElevenLabs WebSocket Turbo Stream: Direct chunk streaming over WebSocket (`/stream-input`) replacing blocking REST endpoints.
  • 📚 Domain Data Grounding: Structured lesson scripts and SQLite vocabulary databases constrain dialogue to lesson objectives.

PROJECT 02 • MULTIMODAL VISION AI & RULE ENGINE Quick-Quote AI (Furniture_Soft)

Vision AI Interior Quotation & Automated Bill-of-Quantities (BoQ) System

An automated spatial and item recognition engine transforming 3D perspective renders and floorplans into strictly typed BoQ estimates for custom wood manufacturing workshops.

PYTHON GEMINI-VISION PYDANTIC POSTGRES-JSONB NEXTJS

🎯 Key Production Bottlenecks

  • ⚠️ 45-Min Manual Parsing: Workshop owners lost nearly an hour manually typing dimensions into Excel for every prospective client.
  • 🧮 Math & Schema Hallucinations: Pure LLM outputs failed at calculation arithmetic and injected unknown JSON keys or malformed structures.
  • 🖼️ Visual Background Noise: Raw Vision models got distracted by non-wood decor (curtains, ceiling lights, appliances) outside workshop scope.

⚙️ Technical Decisions ("Under the Hood")

  • 🤝 AI-Assisted, Human-Approved Workflow: AI generates draft BOM items; human approves or adjusts dimensions in 30 seconds on a Next.js/Shadcn table UI.
  • 🛡️ Pydantic Schema Guard: Enforced strict Pydantic JSON schemas (`extra='forbid'`) via Gemini Flash / Claude Sonnet Structured Outputs to guarantee zero extra fields.
  • 📐 Domain Knowledge Rules Engine: Injected standard carpentry defaults (wardrobe depth 600mm, top cabinet 350mm, 50mm rounding) and prompt domain filtering.
  • 💰 Python Rule Engine + PostgreSQL JSONB: LLM handles entity detection only; 100% exact pricing is computed by Python rule engine querying dynamic workshop JSONB tariffs.
  • ⚡ Async 202 Accepted Job Queue: Decoupled 5–15s Vision LLM parsing via background tasks with SSE/Polling state updates.

PROJECT 03 • DECOUPLED AGENTIC AI & MICROSERVICES WMS Ecosystem (WMS_Root)

Decoupled Warehouse Orchestration & Agentic AI Platform

A high-performance, clean-architecture warehouse ecosystem combining gRPC microservices, ACID transaction isolation, LangGraph stateful AI reasoning agents, and 19 Model Context Protocol (MCP) operational tools.

PYTHON LANGGRAPH MCP-SDK GRPC REDIS-STREAMS CHROMADB

🎯 Key Production Bottlenecks

  • ⚠️ High-Concurrency Inventory Races: Multi-warehouse stock allocation required zero race conditions or overselling under rapid order fulfillment spikes.
  • 🤖 Unsafe Autonomous AI Actions: Integrating LLMs into operational warehouse workflows risks catastrophic inventory corruption without strict execution tools.
  • 🚀 High-Throughput I/O Bottlenecks: Microservice inter-op required sub-millisecond RPC latency and zero database contention.

⚙️ Technical Decisions ("Under the Hood")

  • 🏛️ 3-Submodule Decoupled Architecture: `WMS_Core` (FastAPI + gRPC + PostgreSQL + Redis), `WMS_AI_Services` (LangGraph + Hybrid RAG + Groq), and `WMS_MCP_Server` (19 MCP Tools).
  • 🛠️ 19 Model Context Protocol (MCP) Tools: Exposed standard stdio/SSE tools enabling AI agents to query stock, generate barcodes, and lock allocations safely.
  • 🔍 Hybrid Vector + BM25 RAG: Combined ChromaDB vector embeddings with BM25 keyword matching for zero-hallucination document retrieval.
  • 🔒 ACID & Distributed Locking: Row-level PostgreSQL locks combined with Redis `SET NX EX` + Lua scripts for atomic distributed concurrency control.
  • ⚡ Redis Stream Micro-batching: Implemented `IngestBuffer` using `asyncio.Queue` (20ms buffer) writing to Redis Streams via custom raw socket RESP parser.

🚀 Redis Stream Micro-batching (`IngestBuffer`)

Accumulates single event payloads into an `asyncio.Queue` over a 20ms window and performs bulk pipeline execution via custom raw socket RESP parser.

api_gateway/ingest_buffer.py Python 
async def _flush_loop(self):
    while self.running:
        await asyncio.sleep(0.02)  # 20ms micro-batch window
        batch = []
        while not self.queue.empty() and len(batch) < 500:
            batch.append(self.queue.get_nowait())
        if batch:
            await self.raw_resp_pool.xadd_batch("stream:inventory_events", batch)

🛡️ ENGINEERING PHILOSOPHY

How I Build Production AI Systems

Core engineering principles to ensure AI applications survive real-world scale and production traffic.

⚙️

1. Deterministic Over Magic

Never trust unvalidated raw LLM text strings. Every payload must pass strict schema validation, type checks, and bounded ranges before touching production databases or clients.

⏱️

2. Perceived Latency is UX

When model generation takes time, intelligent audio buffering, streaming tokens, pre-buffered audio fillers, and optimistic UI updates make applications feel instant.

🔄

3. Graceful Fallbacks by Design

AI APIs fail, timeout, or hit rate limits. Robust systems require automated retries, exponential backoffs, circuit breakers, and fail-safe text degradation.
